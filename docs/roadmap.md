# Neow 路线图

总原则（从三位前辈学到的）：
- **AlphaGo**：先站在"人类（或更强机器人）数据"肩膀上，再 RL 超越。冷启动 self-play 是下策。
- **Mortal**：监督底座的规模与质量决定最终上限；RL 只做微调与修正。
- **Pluto**：环境对接、并发、速度这些"无聊的工程"才是真正决定成败的部分。

推进顺序（2026-10 调整）：**模拟器优先**——它是数据、IL、RL、对拍共同的地基；
桥接模组（neow-bridge）后置到 **P2**，即大规模 RL 投入前的最后正确性关卡，期间不需要装游戏。

---

## P0 高速模拟器（3-6 周，最重的工程，子项目：`neow-sim/`）

**目标**：离线可跑、确定性（种子可控）、≥1000 局/秒/核 的规则复刻。

- [ ] 范围界定：战斗层精确复刻；地图/事件/商店按游戏规则实现
- [ ] 语言：Rust；参考 `sts_lightspeed` 的实现（它是现有最强启发式 bot，战斗逻辑可直接对照）
- [ ] 绑定：pyo3 暴露给 Python，gym 接口（协议 `docs/protocol.md`）
- [ ] 里程碑推进：M1 卡牌原语 → M2 单场战斗闭环（铁甲战士 vs 颚虫）→ M3 整局闭环
- [ ] **规则级验证**（对拍前的正确性手段）：对游戏 wiki 数据表 + lightspeed 行为写单测；卡牌/遗物效果逐个过关
- [ ] **验收**：整局闭环可跑；单核 ≥1000 局/秒；规则级单测全绿

**这是整个项目最大的分水岭**：AlphaStar 用官方回放+集群，Mortal 依赖天凤服务端，我们必须自己造"服务端"。

## P1 模仿学习底座（2-4 周，子项目：`neow-ai/`）

**目标**：学出 Mortal 的"监督底座"——一个像样的起点策略。

- [ ] 数据源：`sts_lightspeed` 在模拟器中生成对局（它是 A20 高胜率 bot，相当于"凤凰卓玩家"）
  - 规模目标：≥500 万场战斗、≥5000 万决策点
  - 多样性：不同角色、卡组、遗物、事件分支（必要时混入温度/噪声避免过窄）
- [ ] 观测编码：实体集合（卡牌×升级×数值、遗物、药水、地图节点）→ token，transformer encoder
- [ ] 动作解码：自回归 `(动作类型 → 实体 → 目标)`，全程 mask
- [ ] 多任务头：policy + value(整局胜率) + 辅助头（预测抽牌堆构成、下回合抽牌 → 隐式学 belief）
- [ ] **验收**：IL 策略在固定 1000 种子集上 A20 通关率 ≥ lightspeed 的 70%

## P2 环境桥接与对拍（1-2 周，子项目：`neow-bridge/`——做成 STS 模组）

**目标**：外部进程完整观测/控制真游戏，并完成 M4 对拍。

- [ ] NeowBridge 模组：**fork CommunicationMod** 起步（ModTheSpire + BaseMod 技术栈）
- [ ] 模组通过本地 socket / stdio 收发统一 gym 协议 JSON（`docs/protocol.md`）
- [ ] 相比原版的增强：去动画提速、暴露/固定 RNG 种子、批量动作、补全缺失状态字段
- [ ] Python 侧薄封装（放 `neow-ai/env/`，spirecomm 可作参考）：
  - `obs = env.reset(seed)` → 完整游戏状态
  - `obs, r, done, info = env.step(action)`
- [ ] **M4 对拍**：同种子、同动作序列，模拟器 vs 真游戏逐状态 diff，黄金用例 100% 通过
- [ ] **验收**：无人值守跑局 + 对拍全绿

定位：**大规模 RL 投入前的最后正确性关卡**——别在错误的模拟器上烧卡。演示/直播形态也在此之后再做。

## P3 强化学习自迭代（持续，核心研究，子项目：`neow-ai/`）

**目标**：超越老师。相当于 AlphaGo 的 RL 阶段，但对手是环境随机性而非自己。

- [ ] 算法：PPO 起步（稳定、好调）；规模化后可换 IMPALA 式分布式 actor
- [ ] 奖励：终局胜负为主 + 轻度 shaping（战斗血差、金币、卡组质量代理），shaping 权重必须小
- [ ] IL 初始化 + KL 锚定防止崩坏；旧 checkpoint 池混合采样防退化
- [ ] 并发：模拟器多进程 rollout（每核一实例），GPU 只做学习
- [ ] **验收**：固定种子集 A20 心脏击杀率 ≥ lightspeed 同种子成绩

## P4 战斗内搜索（2-4 周）

**目标**：把 policy/value 网络的"直觉"升级为 AlphaGo 式的"深算"。

- [ ] 战斗是最典型的部分可观测子博弈：对洗牌顺序做 K 次 determinization 采样
- [ ] 每个采样下跑浅层 tree search，policy 先验定序、value 截断展开
- [ ] 地图/商店/事件决策仍用纯网络（搜索收益低、分支意义不同）
- [ ] 受游戏内形态硬约束（无S/L、非穷举、单决策 ≤1s）
- [ ] **验收**：同权重网络，开/关搜索的胜率差 ≥ 3pp 且单步耗时 < 1s

## P5 评测与出圈（持续）

- [ ] 基准协议：1000 固定种子 × 4 角色 × A20，报告通关率/心脏击杀率/场均数据
- [ ] 全部成绩以**游戏内形态**计量：无 S/L、非穷举（单决策 ≤1s）、不窥探隐藏信息
- [ ] 对手盘：lightspeed、人类顶尖录像
- [ ] **Mortal 式 Review 工具**：导入任何一局（真人或 AI），标注每步的 AI 推荐与胜率变化 → 这是最容易出圈的产物
- [ ] （可选）直播/录像：Neow 逐层登塔，实时显示胜率估计

## 里程碑与指标一览

| 阶段 | 核心指标 | 参考线 |
|---|---|---|
| P0 完成 | 模拟器整局闭环 + 性能 | 单核 ≥1000 局/秒 |
| P1 完成 | IL 策略 A20 通关率 | lightspeed 的 70% |
| P2 完成 | 真游戏对拍通过率 | 100% |
| P3 完成 | RL 策略 A20 心脏击杀率 | ≥ lightspeed |
| P4 完成 | 搜索增益 | ≥ +3pp |
| 人类顶尖 | A20 心脏击杀率 | 约 30-50%（供参考） |
