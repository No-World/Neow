# Neow 架构设计

## 1. 双引擎架构

```
┌──────────────────────────────┐        ┌──────────────────────────┐
│  真游戏 (Java, Steam)         │        │  高速模拟器 (Rust)         │
│  + CommunicationMod          │        │  战斗/地图/事件规则复刻     │
│  用途：对拍校验、最终评测、     │        │  用途：数据生成、RL 海量rollout│
│  （可选）直播演示              │        │  ≥1000 局/秒/核，种子可控   │
└──────────────┬───────────────┘        └────────────┬─────────────┘
               │        统一 gym 协议（同一套代码）      │
               └──────────────────┬───────────────────┘
                                  ▼
                    ┌─────────────────────────┐
                    │  训练/推理层 (Python)      │
                    │  IL → PPO → 战斗内搜索     │
                    └─────────────────────────┘
```

关键决策：**模拟器是训练主力，真游戏是“裁判”**（P2 对拍保证两者行为一致）。

子项目映射：真游戏侧 = `neow-bridge/`（NeowBridge 模组，fork 自 CommunicationMod）；模拟器 = `neow-sim/`；训练/推理层 = `neow-ai/`。三者共享 `docs/protocol.md` 定义的统一 gym 协议。

## 2. 观测编码（Observation）

原则：**实体集合 + transformer**，天然支持任意卡组构成与新卡。

| 组 | 内容 | 编码 |
|---|---|---|
| 手牌 | 卡牌ID、升级、费用、数值（格挡/伤害/魔法数字）、可用性 | entity token |
| 抽牌堆/弃牌堆/消耗堆 | **集合**（顺序不可见，这正是 belief 问题） | entity token（无序） |
| 卡组 & 遗物 & 药水 | ID + 数值状态（充能、计数器） | entity token |
| 敌人 | ID、HP、格挡、力量/易伤/虚弱等 buff、意图 | entity token |
| 地图 | 节点类型、路径可达性、层数、已探信息 | 图结构 token |
| 全局 | HP/金币/能量/药水栏位/A 等级/角色 | 全局特征向量 |

辅助监督：预测"抽牌堆构成/下回合抽到的牌"——强迫网络学出洗牌 belief。

## 3. 动作编码（Action）

结构化自回归，杜绝巨型 flat softmax：

```
动作 = 动作类型 → 实体(卡/药/遗物/地图格/商品/事件选项) → 目标(敌/我/无)
```

- 每级都有合法动作 mask（能量、手牌、目标合法性由引擎给出）
- 决策粒度：出牌、能力、药水、遗物、地图路径、商店买卖、事件选择、休息选项

## 4. 网络

```
entity tokens ──► Transformer Encoder (≈6-12层) ──► 主干特征
                                                    ├─► policy head（自回归×3级）
                                                    ├─► value head（整局胜率，标量）
                                                    └─► belief head（抽牌堆预测，辅助）
```

- 规模参考 Mortal：几十 M 参数量级足够；实体编码让参数与卡池解耦
- 战斗内 value（本战胜率/血差）可作中间头，服务 P4 搜索与 shaping

## 5. 训练流水线

**P2 IL**：lightspeed 对局 → (obs, action, 终局胜负) 三元组流 → 交叉熵 + value 回归。
**P3 RL**：模拟器多进程 rollout（每核一实例，CPU 数百核起步）→ 本地 buffer → PPO 更新；IL 权重初始化 + KL 锚定。
**P4 搜索**：仅战斗内启用。K 次洗牌 determinization → 浅层树，policy 定序、value 截断。

## 6. 评测协议

- 固定 1000 种子（公开、冻结，任何人可复现）
- 4 角色 × A20，统计：通关率、心脏击杀率、场均金币/血量曲线
- 汇报格式：每版本 checkpoint 一张榜（类似 kata-go 的 eval ladder）

## 7. 技术选型清单

| 组件 | 选型 | 备注 |
|---|---|---|
| 模拟器 | Rust + pyo3 | 对照 sts_lightspeed（C++）实现 |
| 真游戏桥 | `neow-bridge/`：NeowBridge 模组（fork CommunicationMod，ModTheSpire+BaseMod） | 评测/对拍/演示/直播 |
| 网络 | PyTorch | 单机多卡可覆盖本项目规模 |
| IL/RL | 自写 PPO 或 TRLib/RLLib | 先简单后正确 |
| 对局存储 | zstd 压缩 JSONL → parquet | (obs_hash, action, outcome) |
| 搜索 | 自写 alpha-beta/MCTS 混合 | policy prior + value cutoff |

## 8. 推理预算与游戏内形态（硬约束）

最终形态在游戏内实时运行，硬性约束：

| 约束 | 含义 | 落点 |
|---|---|---|
| 无 S/L | 不存档读档重试/反悔/探信息 | neow-bridge 不提供任何存档操作；评测协议为连续对局 |
| 非穷举 | 单决策预算 ≤1s：K≤64 次洗牌采样 × 有界浅搜索，禁止全枚举 | inference/ 的搜索实现带预算参数 |
| 不窥探 | 只用合法可见信息 | protocol.md 观测 schema（draw_pile 只有集合） |

两档形态：
- **研究档**（离线）：预算可放宽，用于上限探索与消融实验
- **游戏内档**（在线）：严格执行上述约束，对外成绩一律以此档为准

### 信念与诚实型搜索（实现要点）

- 信念 = 抽牌堆未知排列 × 怪物未来 RNG 轨迹（+ 随机插入位置、Runic Dome 隐藏意图）——**两者都必须采样**，只采牌序会系统性低估风险
- 已知位置牌（置顶/置底/沉底）固定，不参与信念采样
- PIMC/确定性化适用：STS 的隐藏信息来自自然随机而非策略对手，经典非策略性缺陷基本无害
- 战斗价值头目标：-ΔHP + 资源项（药水消耗、卡组永久变化如消耗/升级）
